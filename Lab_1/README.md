## Результаты

- sandbox/Монгуш.asm — FASM, Linux x86, 32 бита.
- sandbox/Монгуш — исполняемый файл; Монгуш.o — объектный файл.
- sandbox/С_version.c — аналогичная программа на C (первая С в имени русская).
- sandbox/C_version — исполняемый файл C-программы, ELF 32-bit.
- sandbox/Disassemble — вывод gdb для _start и main.
- Work — результаты 12 заданий с файлами.
- Work_files — журнал реально выполненных команд Bash.

Обе программы выводят фамилию, имя и отчество с отдельных строк.
Результаты сравнивались с ожидаемым текстом командой cmp; различий нет.
Проверены копии файлов, обратный порядок строк, gzip и список архива tar.

## Как собрать и запустить снова

В терминале Linux Codespaces:

```bash
cd Lab_1/sandbox
fasm Монгуш.asm Монгуш.o
ld -m elf_i386 -o Монгуш Монгуш.o
./Монгуш
gcc -m32 -g -O0 -fno-pie -no-pie С_version.c -o C_version
./C_version
file Монгуш C_version
```

## Что происходит в ассемблере

Регистры eax, ebx, ecx, edx хранят значения внутри процессора.
mov записывает значение в регистр. int 0x80 вызывает ядро Linux.
Для write: eax=4, ebx=1 (вывод в терминал), ecx=адрес текста, edx=длина.
Для exit: eax=1, ebx=0 (успешное завершение).
db задаёт байты текста, 10 означает перевод строки.
$ - message вычисляет длину в байтах; это важно для русских букв UTF-8.
FASM переводит инструкции в машинный код в объектном файле; ld создаёт
исполняемый файл. gdb показывает инструкции готовых программ.

## Нестыковки условия и принятые решения

1. В п.1 создана «Лабораторная работа №1!», в п.2 названа «Контрольная
   работа №1!». Созданы обе папки, права 772 выставлены Контрольной.
2. Права 200 у ФИО не позволяют работать внутри каталога без x. Для
   последующих пунктов временно установлены 700, в конце возвращены 200.
3. gzip использован с -k, чтобы сохранить оригиналы для следующих пунктов.
   MyAchiv содержит сжатые файлы на момент выполнения пункта 7.
4. Обратный порядок в п.9 трактуется как обратный порядок строк (tac).
5. П.11 трактуется как список имён файлов и папок, начинающихся с T.
   В Result_3 далее добавлены сведения о ядре и дата выполнения.
6. Git не хранит полные права каталогов. Права проверены в Codespaces,
   команды chmod записаны в Work_files. При клонировании права 200 и 772
   потребуется восстановить отдельно. Пустая Контрольная папка содержит
   служебный .gitkeep, чтобы она сохранялась в Git.

Для просмотра ФИО в VS Code можно временно выполнить из корня репозитория:

```bash
chmod 700 'Lab_1/Work/ФИО'
# После просмотра вернуть права задания:
chmod 200 'Lab_1/Work/ФИО'
```
